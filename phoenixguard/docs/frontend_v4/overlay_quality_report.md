# PhoenixGuard Frontend V4 Overlay Quality Report

## Current Baseline

Reviewed files:

- `Frontend/dashboard/static/window_tracker_dashboard.html`
- `Backend/src/phoenixguard/vision/overlay_geometry.py`
- `Backend/tests/test_overlay_geometry_v3.py`
- `Backend/src/phoenixguard/simulation/overlay_eval/label_clutter_metrics.py`

The backend geometry pipeline is already strong for V4:

- canonical layer list and default visibility exist
- chart bounds clipping is enforced
- broker exclusion boxes can clip or reject chart objects that overlap broker UI
- supply/demand boxes are refined to reaction clusters
- oversized, extreme-aspect, tiny, and unanchored decision boxes are rejected
- same-family boxes are merged
- temporal smoothing is applied when previous geometry exists
- static layer hashing supports low-latency frontend reuse
- truth audit marks decision-valid objects and reports `valid_for_execution`

The current dashboard renderer is functional but not yet a full V4 layered renderer:

- mode support is currently `overlay` and `raw`, not named active-context/full-structure/replay modes
- layer toggles are global booleans
- `visible_default` is generated by backend but the renderer primarily checks `state.layers[layer]`
- labels are placed inside hotspots without a collision pass
- static layer reuse exists and should be preserved

## Quality Gates

| Gate | Target | Current status |
| --- | --- | --- |
| Render budget | `overlay_geometry.render_budget_ms <= 16` | Covered by tests; backend default is 12 ms. |
| Active default | Historical hidden; active-side context visible | Backend supports this via `visible_default`; frontend should consume it in V4 active-context. |
| Broker clipping | Chart boxes cannot cover broker panels | Backend supports broker exclusion clipping/rejection. |
| Label clipping | No visible label extends outside chart bounds | Measurement helper exists; renderer placement pass is still needed. |
| Label collision | No high-priority active labels overlap | Measurement helper exists; renderer collision resolution is still needed. |
| Truth separation | Historical/debug overlays cannot imply execution permission | Backend truth audit exists; frontend copy/styling should keep this separation. |

## Label Collision Metric

Use `evaluate_label_clutter_metrics` from `Backend/src/phoenixguard/simulation/overlay_eval/label_clutter_metrics.py` on candidate label boxes.

Recommended promotion thresholds for active-context:

- `invalid_label_count == 0`
- `clipped_count == 0`
- `overlap_count == 0` for labels with priority `broker_controls`, `active_council_decision`, active-side `trigger_zones`, and nearest `supply_demand`
- `max_overlap_ratio <= 0.12` for lower-priority visible labels
- hidden labels must keep `aria-label`

Recommended thresholds for full-structure and historical-replay:

- `invalid_label_count == 0`
- `mean_clipped_area_ratio <= 0.03`
- `max_overlap_ratio <= 0.25`
- overlapping lower-priority labels may be abbreviated or hidden

## Clipping Review

Backend clipping occurs in `sanitize_overlay_box` and `_clip_against_broker_exclusions`.

Expected V4 frontend clipping:

1. Resolve the box into the active image coordinate space.
2. Convert to CSS percentages.
3. Clamp display bounds before DOM insertion.
4. Build candidate label bboxes from the clamped hotspot and text dimensions.
5. Clip label candidates to chart bounds or image bounds.
6. Hide or abbreviate labels that fail collision thresholds.

Frontend clipping must be idempotent and must not mutate the backend payload.

## Active-Context Risk Notes

The highest-risk visual failure is mixing historical replay with live active context. This can make old structure appear actionable. Keep `historical_replay` hidden in active-context and visually muted in replay mode.

The second highest-risk failure is label overlap around trigger/target zones. When labels collide, preserve the hotspot and inspector click target, but hide the lower-priority text. The chart should remain readable before it is verbose.

The third highest-risk failure is broker control drift. Broker controls are window-space only and should be skipped when the visible image is a chart crop.

## Recommended V4 Acceptance Checklist

- Active-context renders only `visible_default` objects plus user-pinned overrides.
- Raw mode suppresses chart overlays and retains compatible broker controls.
- Historical replay never appears after returning to active-context unless explicitly pinned.
- Static layer reuse is still keyed by `static_layer_hash`.
- Label collision pass runs before DOM insertion.
- `overlay_geometry.truth_audit.valid_for_execution === false` is surfaced in diagnostics/execution UI without blocking non-execution chart study.
- Automated screenshot or DOM tests cover crowded trigger zones, full-window broker captures, and chart-crop captures.
