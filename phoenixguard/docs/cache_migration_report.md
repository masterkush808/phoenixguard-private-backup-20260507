# PhoenixGuard V3 Cache Migration Report

Generated by Agent 5 for the PhoenixGuard Model Council execution refactor.

No files were destroyed or cleared by this pass. This report classifies the current repo/runtime artifacts so the controlled migration can back up or reject stale state without touching model weights, calibration, memory source examples, user config, or training data.

## V3 Runtime Schema

Required cache schema:

```text
PG_CACHE_V3_MODEL_COUNCIL_EXECUTION
```

Required execution packet schema:

```text
PG_EXECUTION_PACKET_V3
```

Every trusted V3 cache object must carry:

```text
cache_schema_version
created_epoch
session_id
symbol
timeframe
frame_id
capture_count
state_version
input_frame_hash
viewport_hash
model_version_hash
preprocess_version_hash
decision_schema_version
calibration_profile_id
```

Runtime validation is implemented in:

```text
phoenixguard/runtime/cache_v3.py
```

Authoritative execution packet construction and validation lives in:

```text
phoenixguard/execution/packet_v3.py
```

`phoenixguard/runtime/cache_v3.py` shares the same schema constants and delegates live execution packet validation to the authoritative packet validator, then exposes Agent 5-friendly freshness reasons for observability/runtime callers.

Old or missing cache schema versions are rejected at validation time. V3 cache records also invalidate on symbol, timeframe, session, input frame hash, viewport hash, model version, preprocess version, calibration profile, packet schema, expiry, and non-advancing frame/capture/state counters.

## Migration Rules

1. Stop live clicking before migration.
2. Preserve calibration, model weights, memory examples, training data, and user configuration.
3. Backup old latest/session/observer/dashboard/replay state to a timestamped folder.
4. Clear or quarantine old state after backup.
5. Restart services with V3 cache validation enabled.
6. Reject any object missing `PG_CACHE_V3_MODEL_COUNCIL_EXECUTION`.
7. Reject any execution packet missing `PG_EXECUTION_PACKET_V3`.
8. Keep Level 3 forensic logs for audit and replay only; never treat them as live execution authority.
